Query Any Database

FlexQL is a compiler-style query engine that converts untrusted filter input into validated, injection-safe queries for SQL, Sequelize, MongoDB, and more.

View on GitHub Live Demo →
flexql.ts
// Your untrusted API input
const query = "username==heja;age>18,status==active"

// Compile to SQL — injection-safe
const result = FlexQL.compile(query, 'sql')

// ➜ WHERE username = ? AND age > ? OR status = ?
// ➜ values: ["heja", 18, "active"]

// Swap adapter — same query, zero rewriting
FlexQL.compile(query, 'mongodb') // ✅ ready

Why FlexQL

Built for Safety.
Designed for Scale.

Modern applications need flexible filtering without exposing SQL, coupling ORM logic to APIs, or creating injection vulnerabilities.

🧠

Human-Readable Syntax

Queries stay understandable as complexity grows. No nested JSON objects, no raw SQL strings, no ORM-specific conditions.

🔒

Injection-Safe by Design

All values are validated and parameterized. FlexQL never concatenates raw user input — safety is architectural, not optional.

🔀

Customizable Separators

Default ; for AND and , for OR — both are fully configurable to match your domain conventions.

🌍

Adapter-Based Output

SQL, Sequelize, and MongoDB are live today. Elasticsearch is on the roadmap. Compile once, target any backend.

🧱

Real Query Engine

Lexer → Parser → N-ary AST → Adapter. FlexQL understands logical precedence and structure — it's not a string replacement tool.

🧩

Easy to Extend

Create new adapters quickly with the modular architecture. Validated syntax with type checking is included out of the box.

Architecture

Deterministic
Compilation Pipeline

Untrusted input is never executed directly. It passes through a structured pipeline — parsed, validated, and transformed before any backend ever sees it.

01 — LEXER
Tokenize
Normalize raw input into a strict token stream. Reject invalid characters immediately.
→
02 — PARSER
Build AST
Validate token order and construct an N-ary AST. Enforce AND/OR precedence.
→
03 — ADAPTER
Compile
Walk the AST and emit backend-specific parameterized output. Never raw strings.

Under the Hood

Not a String Parser.
A Real Query Engine.

FlexQL constructs a full N-ary Abstract Syntax Tree that captures logical structure, precedence, and intent before any adapter runs.

FlexQL Input
// Input query string
"username==heja;age>18,status==active"

// Parsed as:
// (username == "heja" AND age > 18)
// OR
// (status == "active")

// Separator key:
; → AND (higher precedence)
, → OR (lower precedence)
Generated AST
{
  "type": "OR",
  "children": [
    {
      "type": "AND",
      "children": [
        { "field": "username", "op": "==", "value": "heja" },
        { "field": "age", "op": ">", "value": 18 }
      ]
    },
    { "field": "status", "op": "==", "value": "active" }
  ]
}

Syntax Reference

Complete
Language Spec

FlexQL's syntax is intentionally compact and readable. Every element has a defined role in the compilation pipeline.

Element Description Examples
Identifier Column or field name in your data model username, age, created_at
Operator Comparison operator between field and value == != > < >= <=
; AND separator — binds tighter than OR (customizable) name==x;age>18
, OR separator — lower precedence (customizable) status==a,status==b
Value String, number, boolean, or date literal "heja", 18, true, 2025-01-01
⚠️ Note: Spaces cannot be used as separators in the query string. Use ; and , to separate conditions.
